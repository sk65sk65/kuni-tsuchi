# 国の通知文書リンク集（非公式）

各省庁が公開している通知文書へのリンクを、宛先・改正の種類・添付資料の種類で探せるようにまとめた個人運営のサイトです。国が運営するものではありません。

- サイト本体：`docs/index.html`（GitHub Pages で `docs/` フォルダを公開）
- データ：`docs/data/notices.json`
- 登録しないと判断した通知の一覧：`docs/data/excluded.json`（定期実行で毎回判定し直さないためのもの）

## 登録しない通知

- 厚生労働省の内部向けの訓令
- 個別の医薬品・医療機器の扱いを決めるもので、自治体の事務に関係しないもの（「使用上の注意」の改訂、新医薬品・新医療機器の承認・再審査・使用成績評価、一般的名称、要指導医薬品の指定、希少疾病用・先駆け指定、最適使用推進ガイドラインとそれに伴う保険上の留意事項、日本薬局方、医薬品リスク管理計画、薬価基準の改正、医療機器の保険適用、個別製品の承認申請のQ&Aなど）
- 介護保険最新情報のうち、セミナー・説明会・展示会の案内と、調査研究の成果物の紹介
- 総務省のうち、自治行政局・自治財政局・自治税務局・消防庁以外の局の通知で、宛先に都道府県・市区町村が入っていないもの（例：各府省あて、電気通信事業者あて）
- 消防庁・文部科学省のうち、宛先に都道府県・市区町村（教育委員会・消防本部を含む）が入っていないもの（例：学校法人だけ、大学だけ、事業者だけが宛先）と、研修会・行事・説明会の案内

## データの形（notices.json の notices の1件）

| 項目 | 内容 |
|---|---|
| `id` | 法令等データベース由来は `mhlw-` ＋ PDFファイル名（例：`mhlw-T261002S0020`）、介護保険最新情報は `kaigo-` ＋ 号数（例：`kaigo-1549`。号数がない場合は `kaigo-` ＋ PDFの番号）、総務省は `soumu-` ＋ PDFの番号（例：`soumu-001103053`）、消防庁は `fdma-` ＋ PDFファイル名（拡張子なし）、文部科学省は `mext-` ＋ PDFファイル名（拡張子なし）。重複登録の判定に使う |
| `series` | 号数つきの通知の名前（例：`介護保険最新情報 Vol.1549`）。ない場合は省略 |
| `title` | 件名 |
| `docNumber` | 文書番号（例：`保発0930第5号`）。事務連絡は `事務連絡` |
| `issuedDate` | 発出日（`YYYY-MM-DD`） |
| `ministry` / `bureau` | 省庁 / 局 |
| `recipients` | 宛先区分の配列：`都道府県` `市区町村` `国の機関・関係団体` |
| `recipientsText` | 宛先の原文 |
| `revisionType` | `法律改正` `政令・省令改正` `告示改正` `運用・解釈の変更` `その他` |
| `effectiveDate` | 施行日・適用日（`YYYY-MM-DD`、不明なら空） |
| `fields` | 分野タグの配列 |
| `summary` | 2〜3文の概要 |
| `summaryBy` | `ai`（AI要約）または `manual` |
| `url` | 通知本文のURL |
| `attachments` | `{ name, type, url, inMain }` の配列。`inMain` は本文PDFに同じつづりならtrue |
| `memo` | メモ（公開されます） |
| `addedBy` | `auto`（定期タスク）または `manual` |
| `addedDate` | 登録日（`YYYY-MM-DD`）。30日以内は「新着」表示 |

添付資料の種類：`通知本文` `新旧対照表` `改正後全文` `概要資料` `Q&A・疑義照会回答` `様式・記載例` `法令・告示の本文` `スケジュール` `参考資料`

## 出典と利用条件

通知の情報は各省庁のウェブサイトを出典とし、概要は出典をもとにAIが作成・加工したものです。

## GitHub Actions での新着収集と公開

ワークフロー「通知の収集と公開」は日本時間の月〜金曜11:47に実行されます。
対象は上記の5収集元の直近30日分（当日を含む）です。過去分の進捗ファイルは対象外です。

1. Actions でワークフローを手動実行し、`discover` を選ぶと、一覧を取得して未処理候補をログに表示します。
2. リポジトリの Actions シークレット `OPENAI_API_KEY` を設定して、`preview` を手動実行します。公式の本文資料を OpenAI API に送って判定し、登録・除外・保留候補をログに表示します。既定のモデルは `gpt-5-mini` です。API は従量課金で、PDF のページ数や候補の件数で使用量が変わります。試運転と実運用の費用を確認してから設定してください。
3. GitHub Pages の Source を **GitHub Actions** に変更し、リポジトリの Actions 変数 `NOTICES_PAGES_ENABLED` に `true` を設定します。初回は手動の `deploy` で現在の `docs` を公開し、サイトが表示されることを確認します。以後、`main` の `docs` を変更したときも公開します。
4. Claude 側の新着収集を停止できたことを確認し、Actions 変数 `NOTICES_AUTO_PUBLISH` に `true` を設定すると、定期実行で収集結果を公開します。この変数を削除すれば、定期実行は候補の取得だけになります。

更新前に `main` が変わっていれば、その回の反映を中断します。取得や判定ができなかった通知はログで確認してください。保留した通知は対象期間に入っている間、次回も確認します。データのコミット後に Pages の公開だけが失敗した場合は、手動の `deploy` で再公開できます。
